# Android 分析

- 源码工程先从 Kotlin / Java 入口和 Gradle 配置核对 flavor、build type、source set、最终 Manifest、组件生命周期、路由与注入绑定。
- APK 取证先记录版本、包名、构建类型和 SHA-256。复用同一版本已验证的产物；存在空分支、类型丢失或控制流矛盾时，回查方法级指令或其他可靠证据。依赖工具不可用时说明证据缺口，通过可用产物继续。
- 检查原生与 KRN/RN 等动态容器的实际路由、入口、参数、bundle 和降级。记录检索范围。仅有类声明、队列类、截图或未找到 bundle 时保留结论边界。
- 治理按实际展示路径逐条核对普通展示、立即展示、框架或业务队列、去重 ID、关闭与丢弃回调。迁移场景追到队列交接与迟到响应。
- 需要动态页面、缓存、弹窗或配置排查示例时，可读[原有 Android 案例](ai-head-image-case.md)。案例中的具体类、字段和规则只适用于该样本。
